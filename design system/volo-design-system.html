PRINCIPLES

  • The scoreboard comes first. The biggest thing on every screen is a number.
  • One main action. Only one volt-filled button per screen.
  • Say it twice. Status is always a glyph and a word. Color is the third signal, never the only one.
  • Rules, not boxes. Separate with lines. Containers are reserved for the scoreboard and the invite.
  • Money is calm, wins are loud. Risky actions sit behind a menu and a dialog. The win is the only full-volt screen.

TOKENS

Tokens come in three tiers, as in Material and most mature systems. Names run from general to specific.

Color rules

  • Volt means you, safe, win, or the main action. Nothing else is volt.
  • Sky means the opponent. Sky is never a button.
  • Amber and coral never appear without a glyph and a word.
  • No gradients, no glows, no opacity-based text. Exceptions, win surface only: the sunburst rays, the confetti, and dashed rules in the win text color at 28%.
  • Surfaces separate by 1dp lines first, surfaceRaised second. No drop shadows except the FAB.
  • Secondary text on volt uses onWinMuted, never translucency.

TYPE

Big Shoulders Display (weights 800, 900) carries every number and display word. Schibsted Grotesk (500, 600, 700) carries everything else. Both are free under the SIL Open Font License from Google Fonts, and the static TTFs for Android are in the download.

TokenFaceSize / lineWeightUse

Type rules

  • All numbers are display type: clocks, stakes, amounts, prices.
  • Addresses and transaction hashes are the exception: Schibsted BodyMd so every character stays legible.
  • Sentence case everywhere. Capitals appear only inside display words such as WON and DUELS. No tracked small caps.
  • Sizes are in sp. Clamp scoreboard clocks at 1.3× font scale so they never overflow.
  • Nothing under 12sp. Secondary text is 14sp.
  • Times read mm:ss on the scoreboard and “18 min” in sentences. Keep a number and its unit together.

Shape

sm 6 tape tracks · md 14 scoreboard, invite, app tile · full buttons, FAB, nav indicator. Three shapes, no others.

Screen anatomy

  • Draw edge to edge and read system bars from WindowInsets. Never hard-code the status bar height.
  • Top-level screens use a large display title. Detail screens use a 56dp app bar with back and an overflow menu.
  • Lists that carry a FAB get 88dp bottom padding so the last row can scroll clear of it.
  • Detail screens keep 24dp clear above the gesture bar.

MOTION

TokenValue
  • One orchestrated moment per screen: the live duel draws markers then the lead; the win drains the pot while the amount counts up.
  • Everything else is still. No looping decoration except the pot’s slow wave and win confetti.
  • With reduced motion on, skip animation and show final values immediately.

ACCESSIBILITY

  • Touch: every tappable thing is at least 48dp wide and tall, with 8dp between neighbours.
  • Not color alone: every status carries a glyph and a word.
  • TalkBack: the scoreboard reads as one sentence, for example “You, 18 minutes 42 seconds, safe. alex.skr, 27 minutes 10 seconds, at risk. You are ahead by 8 minutes 28 seconds.” Mark tape markers decorative and give the container that sentence. Pot reads “Pot, 10 dollars, both stakes locked.”
  • Contrast: every pair in the table passes AA, with a lowest ratio of 5.5.
  • Back: support predictive back; the win screen’s close button and system back both return to Duels.

BUILD

Download contains: tokens.json (design-token format), kotlin/ (Color, Type, Dimens, Theme), fonts/ (static TTFs + licenses) and this page.

  1. Copy the TTFs from fonts/ into app/src/main/res/font/. File names are already valid Android resource names.
  2. Copy the four Kotlin files into ui/theme/ and fix the R import to your package.
  3. Wrap the app in VoloTheme { }.
VoloTheme {
    Text("18:42", style = VoloText.DisplayClock, color = Volo.colors.you)
    Text("27:10", style = VoloText.DisplayClock, color = Volo.colors.opponent)
    Button(shape = VoloShape.Full, modifier = Modifier.height(VoloSize.ButtonStd)) {
        Text("Lock TikTok", style = VoloText.TitleSm)
    }
}

Material components still work because Material’s color, type and shape slots are mapped, and Volo’s extra roles (you, opponent, warning, danger, win) are added through a CompositionLocal, which is Android’s recommended way to extend Material. Buttons need VoloText.TitleSm passed explicitly, since Material’s default button label is 14sp.

OPEN ITEMS

  • Lost is decided: full-bleed coral mirror of win (option B). Recovery lock is amber as drawn. A unilateral forfeit state is still open.
  • Create components are specified (app row, chips, field, review row, stepper, checklist). Still open: empty and error states for lists.
  • No light theme yet, by decision. Add a second tier-1 mapping when you want one; no component changes.
  • App tiles are placeholders. Use each app’s real icon from the system at runtime.
